# D · 2026-10-11 · Gazetteer snapper on E's gold set

- **Who:** D · **When:** 00:35-00:55 IST
- **Goal:** measure the real snapper (`GazetteerSnapper`, used by `RuleSuggestionEngine`): right chips, wrong chips and missed chips, with counts.
- **Setup:** `core` at the working tree after commit `6e779ae` plus the fuzzy fix below; JDK 17, Gradle 9.1.0. Gold: E's `gold_v1.jsonl` + `gold_homophones.jsonl` from `origin/e/data-eval` (`156a7be`), **dev split only** (33 items; the holdout split was not opened). Site: the team's real campus list `dev/site/campus.json`, because the gold uses real campus names. Every gold `location` and `equipment_asset` value is a case (55). Harness: `core/src/test/kotlin/.../suggest/SnapperEvaluation.kt`, run with
  `SNAPPER_EVAL_GOLD=<gold files> SNAPPER_EVAL_SITE=dev/site/campus.json SNAPPER_EVAL_OUT=<report> ./gradlew --no-daemon :core:test --tests "*SnapperEvaluation"`.
- **Two sets:**
  - **Clean:** the value exactly as typed in the gold. This measures false alarms: a chip on input that was already right.
  - **Synthetic mishearings:** the same values with digits and single letters spoken as words ("Seminar Hall 2" -> "seminar hall to", "Himalaya 105" -> "himalaya one oh five"). **Generated, not real recognition errors**: B's accent-contest transcripts will replace this set.
- **Judging:** a chip is right when it names the site entry the gold value (or one of its alts) names. "No chip" is right when that name already appears in what was heard. A place not on the site list should get no chip.

## Run 1 (before the fix): 3 false alarms
| Set | n | right chip | right no-chip | wrong chip | missed | unknown place, no chip | **unknown place, chip** |
|---|---|---|---|---|---|---|---|
| Clean | 55 | 10 | 5 | 0 | 8 | 29 | **3** |
| Synthetic | 9 | 5 | 0 | 0 | 0 | 4 | 0 |

The 3 false alarms all cut a longer, more specific place down to a site name with the same start: "near the Felicity Ground gate" -> Felicity Ground, "Nilgiri parking" -> Nilgiri Block, "fire alarm" -> KRB Fire Alarm Panel. The same effect made "Kadamba Mess kitchen" -> Kadamba Mess and "North mess kitchen" -> Palash Mess; run 1 counted those as right only because the gold lists the mess as an alt, but the chip drops "kitchen". Cause: Jaro-Winkler rewards a shared prefix, and the fuzzy step compared whole strings. Run 1 also over-counted misses: "near the Football Ground" needs no chip, because the name is already there.

**Fix (test-first, `fuzzyNeverDropsWordsFromAMoreSpecificPlace`):** fuzzy matching only fixes spelling, so it needs the same number of words, and the score is the weakest word pair. The judge now counts "name already present" as a right no-chip.
